# 从“电视答题”到家庭学习终端：通用实现方法

本版已经实现课程题库与网页练习流程。下面把电视侧的实现路径、限制和验收入口列出来，
供后续按机型开发；**这些步骤不是已经完成的电视部署回执**。

## 1. 先定义要交付的能力

一个家庭可能需要自愿练习，另一个家庭可能希望在观看一段时间后提醒答题。
先约定对象、规则、退出方式，再选择权限；“能运行 Android”不等于“任何玩法都能实现”。

| 层次 | 需要解决的问题 | 本项目状态 |
| --- | --- | --- |
| 内容 | 课程、学习阶段、单元、题目来源、答案与解析 | JSON 格式、示例、校验与编辑预览已实现 |
| 交互 | 大字、可见焦点、方向键、确认、返回 | 已实现网页参考流程，实体遥控器待验 |
| 流程 | 练习、反馈、错题复习、模拟观看计时 | 已实现当前网页内的演示 |
| 系统 | 外部应用计时、覆盖提示、开机和待机恢复 | 尚未实现电视原生适配 |
| 交付 | 签名 APK、权限引导、升级保留数据、退出和卸载 | 尚未提供 APK，须按真机验收 |

## 2. ADB 与日常业务分别解决什么

ADB 是电脑与已授权 Android 设备间的安装、调试工具；手机与电视可以共用这一层思路。
电视与手机可能有不同的调试入口、USB 角色、安装限制、待机网络和遥控器行为，不能复用一次手机测试作为电视通过记录。

日常换题、改规则、看学习记录，则应由应用本身负责，不以长期开放调试端口代替产品功能。
跨城调试还需要设备所在地的正常授权接入；同一 Wi-Fi 的连接方法不是互联网远控通道。

本参考实现走最简单的数据路径：

```mermaid
flowchart LR
  A[原创或已授权的课程内容] --> B[JSON 校验与人工复核]
  B --> C[电脑预览题目和规则]
  C --> D[电视宿主适配]
  D --> E[本人授权与逐项实机验收]
  E --> F[可交付版本与维护说明]
```

正式产品如需家长远程换题，建议采用经过认证、最小权限的应用协议，
支持题库版本与摘要、完整校验后原子替换、失败保留旧库、断网缓存和授权撤销。
**本版没有实现这个远程接口**。不要直接在电视上开一个无认证 HTTP 服务来提供解锁或安装能力，
也不要把 ADB 端口转发到公网。

## 3. 先让内容层独立工作

`web/core.js` 提供题库校验、选题、有限练习会话、待复习题与演示倒计时计算。
`web/app.js` 负责界面、输入和本地选择。
18 道内置题仅验证流程；正式题目按实际学习阶段与课程范围重新制作，保留内容来源。

独立的内容层有三个好处：换课程不重写计时；电视暂时拿不到时仍能审题；
更换电视宿主时能继续使用相同的数据契约和测试样例。

## 4. 再选择电视宿主

### 自愿练习或专用学习入口

可以先让网页运行于设备允许的浏览器，或在合规的原生 WebView 宿主中加载本地资源。
后者还需自己实现 TV 清单与图标、文件导入、生命周期、版本升级和退出。
不要给 WebView 暴露任意执行命令的 JavaScript 桥，也不要把任意远程页面加载进具备高权限的宿主。
第三方 Kiosk 宿主须核对其许可、资源加载方式和退出流程，不能因“全屏”就认为防绕过可靠。

本地 Python 服务只监听电脑回环地址，**不直接提供给电视访问**。
在电视宿主中加载资源是下一步开发工作，不能把本机演示成功写成已经安装 APK。

### 希望在其他视频应用上提醒或中断

需要独立的 Android 原生适配器。可拆成：

- 通过用户允许的系统能力识别实际观看状态，明确按墙上时间还是有效观看累计。
- 用单调时钟核算当前会话；持久化时区分启动会话与跨重启记录，防止重启后误用旧计时。
- 到期标记“待练习”；只有在系统允许的时机展示提示或 Activity，处理后台启动限制。
- 题目完成或家长选择退出后释放覆盖层、停止相应计时，不遗留拦截状态。
- 待机、断网、升级、进程被回收、权限撤销、遥控器返回与卸载分别验证。

悬浮窗、前台服务、开机广播、使用情况访问和无障碍是不同能力，不是“授予三个权限就全部可靠”。
普通 `TYPE_APPLICATION_OVERLAY` 在关键系统窗口之下，系统也可以调整它的可见性。
Android 的 `KEYCODE_HOME` 正常由系统处理，不直接发给普通应用。
因此不能把一个普通按键处理函数当成“彻底封住 Home”。

设备所有者或专用设备的 Lock Task 是另一种部署模型，有额外的管理配置与授权要求，
不是通用家庭电视的默认权限。本项目不把它与普通侧载 App 混为一谈。
开机、后台与前台服务还受系统版本和厂商策略限制；实施时核对当时的官方规则。

## 5. 电视连接的最小核对路径（到真机阶段再用）

先取得设备本人授权，并使用厂商公开的开发者/安装入口。
Google 官方无线配对要求：手机 Android 11+，TV/Wear OS Android 13+。
旧式厂商网络调试入口是否提供，由具体固件决定；不能根据品牌或年份保证。

以下为**操作说明，项目没有自动执行这些命令**。电脑需先准备 Google 官方 Platform-Tools。
`TV_IP`、`PAIR_PORT`、`CONNECT_PORT` 都要先替换为电视当前显示的值；配对端口和连接端口可能不同。

**步骤 1：配对。只复制执行这一行。**

```powershell
adb pair TV_IP:PAIR_PORT
```

等 `adb` 提示输入配对码后，再单独输入电视给出的码，不把码写入命令或文档。
看到配对成功后才继续；若电视不提供官方无线调试，请查本型号的官方连接方式，勿套用本步。

**步骤 2：连接。只复制执行这一行。**

```powershell
adb connect TV_IP:CONNECT_PORT
```

电视可能需要现场确认授权；确认是目标电视之后继续。

**步骤 3：列出设备。只复制执行这一行。**

```powershell
adb devices
```

目标应显示 `device`。`unauthorized` 或 `offline` 不能继续当成已接通。
同时连着手机时，后续命令必须指定目标，避免误操作另一设备。
完整设备列表、地址、配对码与指纹只留本地，不贴到公开 Issue。

**步骤 4：只读核对。替换目标地址后可整段复制执行。**

```powershell
adb -s TV_IP:CONNECT_PORT shell getprop ro.build.version.sdk
adb -s TV_IP:CONNECT_PORT shell getprop ro.product.model
```

第一行输出 SDK 数字，第二行输出型号；这些结果只确认当前目标和系统，
不证明可安装、不证明后台可靠，也不证明锁屏或答题已通过。
本版没有 APK 安装步骤。设备调试结束后，按设备本身的界面撤销不再需要的调试授权。

## 6. 接定制前，把交付范围写具体

值得收费的工作可以是内容整理、课程映射、遥控器交互、具体机型适配、部署与维护。
先约定题库数量、内容授权、需要的系统能力、验收设备/固件、退出恢复和维护边界。
不要承诺“任意玩法”“所有安卓电视都支持”或“保证防沉迷”。
在完成真机闭环前，适合提供方案评估与原型定制，不应把本仓库展示成现成通用电视锁。
